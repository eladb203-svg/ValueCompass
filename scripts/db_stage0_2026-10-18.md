## 2. RLS

RLS is enabled on all 12 tables. The 4 views have no RLS of their own; they are `security_invoker=true`, so they inherit the caller's RLS on the base tables.

| Table | RLS | Policies (all `TO public`, i.e. anon + authenticated) |
|---|---|---|
| companies | on | none |
| company_listings | on | none |
| company_score_summary | on | none |
| data_update_log | on | none |
| financial_ratios | on | none |
| financial_yearly | on | none |
| market_snapshot | on | none |
| score_details | on | none |
| user_profiles | on | SELECT / UPDATE: `auth.uid() = id`; INSERT: check `auth.uid() = id`; no DELETE |
| portfolios | on | SELECT / UPDATE / DELETE: `auth.uid() = user_id`; INSERT check same |
| portfolio_holdings | on | SELECT / INSERT / UPDATE / DELETE: parent portfolio belongs to `auth.uid()` (EXISTS subquery) |
| user_watchlist | on | SELECT / UPDATE / DELETE: `auth.uid() = user_id`; INSERT check same |

Answers to the questions:
- **Writable with anon/authenticated?** Only the 4 user tables, and only for rows owned by `auth.uid()`. Policies are declared `TO public`, but every condition requires `auth.uid()`, which is NULL for anon, so anon matches no rows. Nothing is writable without ownership.
- **Tables with no policy (blocked for everyone except service_role / postgres):** 8 tables: companies, company_listings, company_score_summary, data_update_log, financial_ratios, financial_yearly, market_snapshot, score_details.
- **Consequence to check:** the 4 overview views join `companies`/`market_snapshot`/`company_score_summary`. With `security_invoker=true` and no SELECT policy on those tables, a logged-in user or anon sees **zero rows** from the views (and cannot read market data directly). If the app reads this data with the anon/authenticated key, it is currently broken or relies on service_role. Needs a decision: public read policy on market-data tables (SELECT only) or keep server-side only.
- **Grants:** `anon` and `authenticated` hold ALL privileges (including TRUNCATE, TRIGGER, REFERENCES) on all 12 tables and 4 views (Supabase defaults). RLS blocks row access, but TRUNCATE and TRIGGER are not governed by RLS. PostgREST does not expose TRUNCATE, so API risk is low, but it is excess privilege.
- **RPC `create_company_with_listing`:** SECURITY INVOKER, EXECUTE granted to PUBLIC/anon/authenticated. It inserts into `companies`; with no INSERT policy that fails for non-service roles, so it works only with service_role. Exposure is limited, but anon can call it via `/rest/v1/rpc`.

## 3. Advisors

Security (2 lints):
- INFO `rls_enabled_no_policy` ×8: the 8 tables above. Intentional-looking (service-role only); see consequence above. https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy
- WARN `function_search_path_mutable` ×2: `public.set_updated_at`, `public.create_company_with_listing`. https://supabase.com/docs/guides/database/database-linter?lint=0011_function_search_path_mutable

Performance (3 lint types):
- WARN `auth_rls_initplan` ×15: every policy on user_profiles (3), portfolios (4), portfolio_holdings (4), user_watchlist (4) calls `auth.uid()` per row; should be `(select auth.uid())`. https://supabase.com/docs/guides/database/database-linter?lint=0003_auth_rls_initplan
- INFO `unindexed_foreign_keys` ×4: `data_update_log.company_id`, `portfolio_holdings.company_id`, `portfolios.user_id`, `user_watchlist.company_id`. (`user_watchlist.user_id` and `portfolio_holdings.portfolio_id` are covered by the composite unique indexes.) https://supabase.com/docs/guides/database/database-linter?lint=0001_unindexed_foreign_keys
- INFO `unused_index` ×3: `idx_company_listings_company_id`, `_symbol`, `_isin` (never used so far; low traffic DB, so don't drop yet).

## 4. Recommendations (nothing applied; each needs your approval)

1. Decide the access model for market data (8 tables / 4 views): server-only via service_role, or add `SELECT` policies `TO anon, authenticated` for companies, company_listings, financial_*, market_snapshot, company_score_summary, score_details. Keep `data_update_log` closed.
2. Rewrite the 15 policies with `(select auth.uid())` and restrict them `TO authenticated` instead of `public`.

4. `REVOKE TRUNCATE, TRIGGER, REFERENCES` (and INSERT/UPDATE/DELETE on the 8 market tables) from anon/authenticated.
5. Add indexes on the 4 unindexed FKs (`portfolios.user_id` and `portfolio_holdings.company_id` matter most for RLS/join speed).
