## 4. נקודות לשיקול דעתך

1. **ח-07 — פרשנות צרה.** יושם רק על ענף `value ≤ 0` (כפי שכתוב בטבלה H). שאר מצבי "לא ניתן להערכה" (V6: ROTCE_norm ≤ 2.5%, TCE₀ ≤ 0, payout חסר, פחות מ-3 שנים; ב-Graham: V5 שנות הפסד תפעוליות, EPS ≤ 0) נשארים `price_score: not_applicable`. הספר (V6, P2) קורא ל"ציון מחיר 0" גם להם. השפעה אילו הורחב: **FLG** (Buffett V6, Graham V5) יקבל ציון מחיר 0. להרחבה — שינוי של שורות בודדות; לא בוצע בלי החלטה שלך.
2. **ח-01 — צורת התווית.** `price_score.label` (טקסט) + דגל. אם נדרש שדה אחר ל-DB (ק5) — נתאים.
3. **ח-06 — ראנרים.** `scripts/run_realestate_pricing_v1…v7.py` מדפיסים `cr["value"]`; יקרוס רק אם יחסר מטבע בקובץ התשואות (USD קיים). לא שיניתי ראנרים.
4. **ח-19 — הראנרים הישנים** (`run_realestate_pricing_v3…v7`) עדיין מכילים את חישוב ה-Q6 לדוחות ההיסטוריים; המנוע אינו תלוי בהם.
5. **C5 נגע ב-`src/providers`** (לא ב-`src/etl`): שתי שורות בנק/נדל"ן. אם רצית אותו ב-facts בלבד — אומר.
6. **golden:** להחליף את `tests/golden/2026-10-20` בחדש (14 קבצים + index) או להשאיר קו בסיס ישן ולהוסיף `2026-10-20-k3`? ממליץ להחליף, כי קו הבסיס צריך לשקף את הרולבוק.
